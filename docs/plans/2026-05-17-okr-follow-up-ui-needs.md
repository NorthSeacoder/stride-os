# OKR Follow-up UI Needs

Date: 2026-05-17

## Context

当前线上 OKR 已完成一轮内容重写，但还有两项明显的产品缺口，会影响后续使用体验与维护效率。

## Pending Needs

### 1. KR 排序

问题：
当前 KR 展示顺序受创建顺序影响，无法按业务优先级手动调整。

目标：
支持在 OKR 详情或编辑界面对 KR 进行排序调整。

最低要求：
- 支持修改同一 Objective 下 KR 的显示顺序
- 排序结果持久化保存
- 列表页与详情页展示顺序一致

后续实现建议：
- 数据层增加或复用 `sortOrder`
- UI 可先做简单的上移 / 下移
- 后续再考虑拖拽排序

### 2. 日历视图

问题：
当前任务与 OKR 缺少时间维度视图，不方便按日期查看计划、复盘与执行密度。

目标：
提供日历视图，用于查看任务分布，并为后续把 OKR / KR 节点映射到时间轴做准备。

最低要求：
- 支持按日历查看任务分布
- 能够看到任务标题与日期归属
- 支持切换基础时间范围（如月视图）

后续实现建议：
- 第一阶段先做 task calendar view
- 第二阶段再考虑把 KR 检查点、复盘节点或关键里程碑叠加到日历中

### 3. Dashboard 补充图表

问题：
当前 dashboard 信息摘要偏文本化，缺少更直观的趋势和结构展示，不利于快速判断执行状态。

目标：
在 dashboard 中补充关键图表，提升对任务、OKR 和执行趋势的可读性。

最低要求：
- 展示至少一类趋势型图表
- 展示至少一类结构型图表
- 图表内容能够直接服务于任务管理或 OKR 跟踪

后续实现建议：
- 可优先补充任务完成趋势、任务分布或 KR 进展图表
- 图表应与现有 dashboard 指标保持口径一致
- 第一阶段优先保证可读性和稳定性，不必一次做复杂交互
