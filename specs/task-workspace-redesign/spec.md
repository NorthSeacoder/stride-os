# Feature Specification: 任务工作区与全局壳层重构

**Workspace**: `task-workspace-redesign`  
**Created**: 2026-05-12  
**Status**: Draft  
**Input**: 用户描述: "全局上需要缩小四周留白、支持全局导航展开/收起；任务模块要重构为三列工作区，包含智能列表、用户清单、任务主列表、详情栏、新建清单、统一新建/编辑弹窗、重复任务配置，并按 SDD 流程推进。当前仍是初版开发，不需要考虑旧模型迁移。"

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 更紧凑且可伸缩的全局工作台壳层 (Priority: P1)

作为高频使用 Stride OS 的用户，我希望 dashboard 壳层减少无效留白，并允许左侧全局导航展开或收起，以便把更多空间留给主工作区，同时保持跨页面的一致定位感。

**Why this priority**: 任务页三列重构建立在新的壳层空间分配之上；如果全局壳层不先收紧并支持导航收展，任务页可用空间会持续不足。

**Acceptance Scenarios**:

1. **[US1-1]**
   **Given** 用户进入任一 dashboard 内页面  
   **When** 页面渲染完成  
   **Then** 主工作区应明显更贴近视口边界，不再被过宽的外层 padding 和大面积壳层留白压缩

2. **[US1-2]**
   **Given** 用户正在查看 dashboard 内页面  
   **When** 用户点击全局导航收起/展开控件  
   **Then** 左侧导航必须在“图标+文字”和“仅图标窄栏”两种模式之间即时切换，且主工作区宽度随之调整

**Edge Cases**:

- **[US1-3]** 在导航收起状态下，当前激活页面仍需可识别，不得只剩无语义图标堆叠
- **[US1-4]** 在较窄桌面宽度下，导航收展后主区仍需保持可用，不得出现主要内容被严重挤压或遮挡
- **[US1-5]** 若本地状态持久化暂时不可用，导航仍必须可手动切换

### User Story 2 - 以三列结构浏览和管理任务 (Priority: P1)

作为需要频繁筛选、查看、完成与编辑任务的用户，我希望任务页面改为三列工作区，以便在同一界面里完成来源选择、任务浏览和详情查看，而不必在多个页面或大块堆叠卡片之间来回切换。

**Why this priority**: 这是用户这轮需求的核心，决定任务模块是否从“表单/卡片集合”转变为真正的工作区产品形态。

**Acceptance Scenarios**:

1. **[US2-1]**
   **Given** 用户进入任务页面  
   **When** 页面渲染完成  
   **Then** 页面必须呈现固定三列：第一栏为智能列表和用户清单，第二栏为任务主列表，第三栏为任务详情

2. **[US2-2]**
   **Given** 用户在任务页面中点击第一栏的某个智能列表或用户清单  
   **When** 选择切换完成  
   **Then** 第二栏标题和列表数据必须同步切换到对应来源，第三栏保留或清空当前选中任务，行为需一致可预期

**Edge Cases**:

- **[US2-3]** 当第二栏或第三栏内容过长时，两栏必须各自独立纵向滚动，且不影响另一栏定位
- **[US2-4]** 当第二栏没有任何任务时，仍需保留清晰的空态和顶部工具条
- **[US2-5]** 当第三栏没有选中任务时，必须显示空态，而不是空白面板

### User Story 3 - 用智能列表和真实清单组织任务来源 (Priority: P1)

作为既需要按时间语义查看任务、也需要按业务清单归类任务的用户，我希望第一栏同时支持智能列表和真实用户清单，以便快速在“今天要做什么”和“某一类工作有哪些任务”之间切换。

**Why this priority**: 第一栏是三列工作区的入口。若来源模型不清楚，第二栏过滤、新建默认归属和后续详情联动都无法成立。

**Acceptance Scenarios**:

1. **[US3-1]**
   **Given** 用户查看任务页第一栏  
   **When** 智能列表区域渲染完成  
   **Then** 系统必须至少展示“所有、今天、明天、收集箱”，并可扩展“最近 7 天”，每项显示对应任务数量

2. **[US3-2]**
   **Given** 用户需要组织一类新任务  
   **When** 用户在第一栏创建一个新清单  
   **Then** 该清单应作为真实数据出现在清单区，并可被第二栏过滤、新建任务归属和编辑任务复用

**Edge Cases**:

- **[US3-3]** “收集箱”必须作为系统保留默认清单存在，且即使用户未创建任何自定义清单，第一栏也应可正常工作
- **[US3-4]** 在非清单视图下，第二栏任务行需要展示清单标识，以免任务来源丢失
- **[US3-5]** 用户清单数量为零时，清单区仍需保留“新建清单”入口

### User Story 4 - 在主列表中快速完成、分组和编辑任务 (Priority: P1)

作为执行任务的用户，我希望第二栏能够直接完成勾选、按时间语义分组、快捷新建和编辑任务，以便减少切换成本并保持工作流连续。

**Why this priority**: 如果第二栏只负责展示，不负责核心交互，那么三列工作区会退化成静态布局升级，达不到效率工具预期。

**Acceptance Scenarios**:

1. **[US4-1]**
   **Given** 用户正在浏览第二栏任务列表  
   **When** 用户点击某行的 checkbox  
   **Then** 该任务必须转为完成态，并从当前开放分组中移出，进入当前视图范围内的“已完成”分组

2. **[US4-2]**
   **Given** 用户位于某个清单或智能列表下  
   **When** 用户使用第二栏顶部快捷添加  
   **Then** 新任务必须按当前来源预填默认归属；若当前来源是“今天/明天”，则应预填对应 `dueDate`

**Edge Cases**:

- **[US4-3]** 任一视图下都必须始终存在“已完成”分组，即使该分组为空或折叠
- **[US4-4]** 在清单视图和智能视图下，任务分组语义可以不同，但都必须遵循统一的时间语义，不得混乱
- **[US4-5]** 已完成任务在视觉上必须弱化，例如灰字、勾选态或低对比样式

### User Story 5 - 在详情栏查看当前任务的核心信息 (Priority: P1)

作为查看任务上下文的用户，我希望第三栏稳定展示当前选中任务的标题和描述，以便在不中断列表浏览的情况下理解任务内容。

**Why this priority**: 第三栏是三列结构成立的关键。如果详情栏不稳定或信息不足，第二栏选择就失去价值。

**Acceptance Scenarios**:

1. **[US5-1]**
   **Given** 用户在第二栏点击某个任务行（非 checkbox）  
   **When** 选中状态生效  
   **Then** 第三栏必须显示该任务的标题与描述，并与第二栏选中态保持同步

2. **[US5-2]**
   **Given** 当前没有任务被选中  
   **When** 第三栏渲染完成  
   **Then** 第三栏必须展示清晰空态，提示用户选择任务

**Edge Cases**:

- **[US5-3]** 当任务描述为空时，详情栏仍需保持稳定布局，不得塌陷
- **[US5-4]** 当第二栏切换来源导致当前选中任务不再属于新来源时，第三栏应同步回到空态或选中新的首项，行为需一致

### User Story 6 - 用统一弹窗创建、编辑和配置重复任务 (Priority: P1)

作为需要录入普通任务和重复任务的用户，我希望新建和编辑共用同一套弹窗字段，并在其中直接配置日期、清单和重复规则，以便减少心智切换并保持录入一致性。

**Why this priority**: 新建/编辑体验决定任务工作区是否真正可用；重复任务又是用户明确提出的功能，必须在同一录入路径中体现。

**Acceptance Scenarios**:

1. **[US6-1]**
   **Given** 用户从第二栏快捷添加或编辑入口进入弹窗  
   **When** 弹窗打开  
   **Then** 系统必须使用统一字段集，至少包含标题、描述、日期、重复配置、归属清单、清除和确定操作

2. **[US6-2]**
   **Given** 用户在弹窗中启用重复功能  
   **When** 用户选择频率与结束方式并提交  
   **Then** 系统必须保存重复定义，并保证当前日期需要出现的任务实例可以被任务页读取到

**Edge Cases**:

- **[US6-3]** 当用户不启用重复时，系统必须创建普通任务，而不是隐式创建重复定义
- **[US6-4]** 当重复任务的结束方式为“按日期”或“按次数”时，未填写必要字段必须阻止提交并给出错误提示
- **[US6-5]** 提交失败时，弹窗不得静默关闭，必须提供错误反馈

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须收紧 dashboard 主壳层的外层留白，使主工作区明显更贴近视口边界，减少无效 padding 对内容宽度的侵占。
- **FR-002**: 系统必须为左侧全局导航提供展开与收起两种模式：展开时显示图标和文字，收起时仅保留图标窄栏。
- **FR-003**: 系统必须提供全局导航收展控件，且交互为即时切换，不依赖页面刷新。
- **FR-004**: 系统应优先持久化全局导航收展偏好到本地状态；若持久化不可用，交互本身仍必须可用。
- **FR-005**: 任务页面必须重构为固定三列布局：第一栏来源导航、第二栏任务主列表、第三栏任务详情。
- **FR-006**: 三列之间必须有清晰分隔；第二栏和第三栏必须各自独立纵向滚动，并优先支持各自栏内顶部工具条吸顶。
- **FR-007**: 第一栏必须包含智能列表区域和清单区域，智能列表至少包括“所有、今天、明天、收集箱”，并可扩展“最近 7 天”。
- **FR-008**: 第一栏每个智能列表与清单项都必须展示任务数量。
- **FR-009**: 系统必须提供“新建清单”入口，允许用户以最小字段集创建真实清单；首版最少包含名称和图标。
- **FR-010**: 系统必须存在系统保留清单“收集箱”，并作为未明确指定清单时的默认归属。
- **FR-011**: 点击第一栏任一智能列表或清单时，第二栏标题和任务数据源必须同步切换到对应来源。
- **FR-012**: 第二栏顶部必须至少包含：第一栏收展控件、当前视图标题、排序占位、更多操作占位、快捷添加入口。
- **FR-013**: 第二栏快捷添加必须根据当前来源预填默认归属；在“今天/明天”视图下应预填对应 `dueDate`。
- **FR-014**: 第二栏任务行必须至少展示 checkbox、标题、在非清单视图下的清单标识，以及截止日期。
- **FR-015**: 点击任务行的 checkbox 时，系统必须切换任务完成态，并将任务归入当前视图范围内的“已完成”分组。
- **FR-016**: 点击任务行的非 checkbox 区域时，系统必须选中该任务并驱动第三栏详情同步更新。
- **FR-017**: 新建任务与编辑任务必须共用同一弹窗与同一字段集。
- **FR-018**: 弹窗中的日期区必须提供快捷选日与日历选择能力。
- **FR-019**: 弹窗中的重复配置必须支持：每天、每周、每月、工作日、周末；结束方式必须支持：一直重复、按结束日期、按重复次数。
- **FR-020**: 弹窗中的归属清单必须来自第一栏真实清单数据源。
- **FR-021**: 当用户启用重复功能时，系统必须保存重复任务定义，并确保当前日期需要出现的任务实例可被读取。
- **FR-022**: 第二栏在用户清单视图下必须按统一时间语义分组，至少覆盖：已过期、今天、明天、未来、无日期、已完成。
- **FR-023**: 第二栏在智能列表视图下必须先按智能来源过滤，再在该范围内提供时间语义分组，并始终存在“已完成”分组。
- **FR-024**: 已完成分组中的任务必须具有明确的完成视觉状态，例如已勾选与标题弱化。
- **FR-025**: 第三栏主要职责必须是展示当前选中任务的标题与描述；无选中任务时必须显示空态。
- **FR-026**: 页面必须维护第一栏选中来源与第二栏选中任务两类核心状态，并用它们驱动列表和详情联动。
- **FR-027**: 任务页必须具备基础的空态、加载态和错误态，包括：无清单、无任务、无选中任务、请求失败、提交失败。

### Non-Functional Requirements *(if applicable)*

- **NFR-001**: 新布局必须在常见桌面宽度下保持主工作区可用，不得因三列与导航收展导致严重遮挡或内容不可读。
- **NFR-002**: 全局壳层改造和任务页重构必须优先服务工作效率，不得用装饰性结构替代清晰的信息层次和操作路径。
- **NFR-003**: 当前仍处于初版开发阶段，本次需求不要求兼容旧任务模型或提供旧数据迁移方案。

### Key Entities *(if applicable)*

- **任务清单**: 真实存在的任务归属容器，包含系统保留清单与用户自定义清单；至少具有名称、图标、类型和数量统计语义。
- **任务**: 用户在第二栏直接看到、勾选、查看详情和编辑的可执行任务实体；使用单一 `dueDate` 表达日期语义。
- **重复任务定义**: 用于描述按何种频率和何种结束条件生成任务实例的定义实体；与普通任务实例分离。
- **智能列表来源**: 基于日期语义或系统默认归属生成的查询视图，例如“今天”“明天”“收集箱”，不是用户自定义清单本身。

## Out of Scope *(if applicable)*

明确不在本次功能范围内的内容：

- 旧任务模型与新任务模型之间的数据迁移设计
- 任务提醒、通知、推送或后台定时任务体系
- 多人协作、权限共享、任务评论
- 富文本或完整 Markdown 编辑器能力
- 排序、更多操作等顶部占位入口背后的完整业务行为
- 超出“名称+图标”最小字段集之外的复杂清单管理能力

## Unclear Questions *(if applicable)*

当前无会阻塞进入 `plan` 的关键歧义。后续若需要进一步细化，可在 `plan` 阶段明确：

- 重复任务定义与任务实例的最小数据边界命名
- 第一栏和全局导航在不同桌面宽度下的具体收缩阈值
